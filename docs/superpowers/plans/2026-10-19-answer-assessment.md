# 答案评判与掌握度实现计划

用户已确认三类评判与掌握度规则，选择 Mac 为主、手机辅助，并要求参考 GitHub 上轻量 AIED 项目后继续实现。

## 范围

- 原创评判提示词参考 AIED annotating-errors-wcf 的错误定位、原因、改法思路；不复制未明确许可的代码。评分与复习间隔由程序校验和计算。
- 三类语言结果：grammar_error、unnatural、correct；taskMatch 独立记录，语法正确但含义不符不计掌握。Listen/拼句按原句复现，普通回忆接受同义表达和符合题目的短语片段。
- 保存原句、错误范围、解释、纠正句、自然替换。仅首次未看答案且当天未练过的独立作答更新掌握度；纠错练习不刷分。两次不同日期的连续独立正确才计经作答验证的稳定回忆。
- 现有手动自评记录保留。新增经作答验证统计与最近 200 次反馈；每卡累计计数和正确日期单独保留，导入导出向后兼容。
- 同参考表达匹配时可本地校验，明确标注来源；其他表达通过本地服务判断。接口失败或结果不合规时不写成绩、不伪造 AI 结果。
- Mac 本地 Node 服务，无新增运行依赖，服务只监听 127.0.0.1，静态资源使用白名单。实现官方 Sign in with ChatGPT：动态注册、PKCE、state/nonce、JWKS 验证、权限检查、保护性本地存储和串行刷新。浏览器与 GitHub 不接收模型令牌。
- 本机网页调用同源评判接口；GitHub Pages 和手机保留基础卡片、匹配校验和备份功能，并清楚说明 AI 需要 Mac 本机服务。手机进度继续通过备份导入导出，不在本次增加公网服务。
- 授权完成后从账户可用模型列表选择；使用官方 Responses API 流式调用，store=false，只有 response.completed 才接受结果。不调用 shell 工具，不自动转为 API Key 付费。

## 文件与验证顺序

1. tests/assessment.test.mjs 与核心回归：协议、非空答案、错误范围、首次作答、跨天掌握、兼容导入、重复请求。
2. assessment.js + core.js：纯评判协议、提示词、结果校验和掌握记录。
3. local/auth.mjs + local/provider.mjs + server.mjs：授权、完成流、受保护本地接口。测试签名/nonce/过期、CSRF、路径白名单、断流和额度错误。
4. assessment-ui.js + app.js + styles.css：提交评判、反馈、揭示标记、取消过期请求、设置与进度页。
5. 更新 README、Pages 打包与研究参考文档，运行全部测试和语法检查，浏览器检查，独立代码审阅后提交推送。真实模型链路需用户在本地设置页完成一次 ChatGPT 授权；测试不使用或伪造订阅令牌。
